# Codex 的远程工作到底是怎么实现的？

我们都知道，ChatGPT 里的 Codex 有一个功能叫做远程工作。

简单来说，就是我们可以通过手机来控制电脑上的 Codex，让它在电脑上读代码、执行命令和完成任务。

但是这里有一个问题：我们的电脑既没有公网 IP，也没有开放任何网络端口，手机到底是怎么找到这台电脑，然后把一条消息传过去，让电脑上的 Codex 开始工作的？

我最近因为想搞清楚这个问题，把它整个的连接流程梳理了一遍。其实它背后的原理并不复杂，核心就是一个云端中继服务，加上两条 WebSocket 长连接。

首先，当我们在电脑上打开 ChatGPT 的 Remote Control 之后，电脑端会主动和 OpenAI 云端建立一条 WebSocket 连接。

这个连接不是云端主动来连接电脑，而是电脑主动连接云端。所以即使电脑藏在路由器后面，没有公网 IP，也不需要在防火墙上开放端口，这条连接依然可以正常建立。

连接建立之后，云端会给这台电脑分配一个 environmentId。可以简单理解成，这是这台电脑在云端中继服务里的地址。

接下来，桌面端会生成一个二维码。我们用手机扫码，完成账号、工作区以及必要的安全验证。

这个配对过程，并不是把电脑上的所有会话和文件都复制到手机，也不是让手机获得整台电脑的控制权。它真正做的事情，是给这台手机增加一条授权：允许它通过云端中继，访问这个 environmentId 对应的 Codex 服务。

配对完成之后，当我们在手机上打开 Remote 页面，手机首先会问云端：我的账号下面，目前有哪些已经授权的电脑？

选中其中一台电脑之后，手机再通过云端中继，请求电脑上的 Codex app-server 返回会话列表。

电脑端会从本地的会话数据库里读取会话标题、工作目录、更新时间和运行状态。手机点开其中一条会话之后，再根据 threadId，读取这条会话具体的历史记录。

所以这里并不是配对完成之后，手机自动拥有了电脑上的所有会话副本。而是手机需要查看什么，再通过中继向电脑实时请求什么。真正的会话权威数据，依然保存在电脑端。

那当我们从手机发送一条消息时，整个过程又是怎么样的？

手机会把消息连同两个关键的信息一起发给云端。一个是 environmentId，告诉云端这条消息要发给哪台电脑；另一个是 threadId，告诉电脑这条消息属于哪一条会话。

云端收到消息之后，会根据 environmentId，找到这台电脑之前主动建立的 WebSocket 连接，然后沿着这条已经存在的连接，把消息推送到电脑上的 app-server。

这里有一个特别容易误解的地方。

虽然 WebSocket 是电脑主动连接云端建立的，但 WebSocket 本身是双向的。连接建立之后，不仅电脑可以给云端发消息，云端也可以随时沿着同一条连接，把消息发回电脑。

它有点像电脑主动给云端打了一通一直没有挂断的电话。手机把指令交给云端之后，云端只需要找到对应的电话线路，再把这条指令告诉电脑就可以了。

电脑上的 app-server 收到消息之后，会找到对应的 threadId，创建一次新的任务。接下来，它会加载这条会话的上下文、当前项目目录、Skills、MCP 和权限配置，然后请求 OpenAI 的模型服务。

模型负责判断接下来要做什么，真正的命令执行、文件读写、Git 操作以及 Computer Use，还是发生在这台电脑上。

执行过程中，电脑端会不断产生新的事件。比如任务已经开始、正在执行什么命令、修改了哪些文件、模型正在生成什么内容，以及任务最终有没有完成。

这些事件会带上 threadId、turnId 和 itemId，通过电脑和云端之间的 WebSocket 返回中继服务。中继服务再把它们转发到手机，所以我们才能在手机上实时看到电脑端的执行过程。

那如果这个时候手机锁屏了，或者网络断开了，会发生什么？

正常情况下，手机锁屏之后，iOS 不会允许一个普通应用永远保持 WebSocket 连接。但是这并不会影响电脑继续执行，因为只要电脑端已经确认收到消息，并且创建了 turnId，这个任务就已经由电脑上的 app-server 接管了。

手机在线的时候，通过 WebSocket 实时接收执行过程；手机锁屏之后，电脑继续工作。等到任务完成或者需要用户审批时，云端再通过手机系统的推送通知提醒我们。

重新打开 ChatGPT 之后，手机会重新建立连接，再根据 threadId 和 turnId，把锁屏期间错过的结果重新读取回来。

所以整套系统真正巧妙的地方，不是做了一套远程桌面，也不是让手机直接连接了电脑。

它真正做的事情，是把控制端和执行端拆开了。

手机只是一个随时可以离开的控制入口，电脑才是持续运行的执行节点，云端中继负责让两边能够互相找到。

而且因为电脑主动连接云端，所以不需要公网 IP，不需要开放端口，也不需要把整个桌面暴露到互联网上。

我觉得这套架构真正值得关注的地方是，未来我们可能不再需要一直坐在电脑前面使用 AI。

只要有一台持续在线的电脑，或者一台远程服务器，我们就可以通过手机随时发起任务、查看进度、处理审批，再让 Agent 在原来的环境里继续工作。

我们远程控制的并不是那台电脑本身，而是运行在那台电脑上的 Agent。
