# Get 笔记同步规则

本地目录重组后，路径与 Get 知识库不再一一同名。同步方向、目标和覆盖范围由用户请求确定；不得通过移除目录数字前缀来推断知识库。没有明确映射的条目先核对，不自动上传、下载或覆盖。

## 现有映射

| 本地内容 | Get 笔记原有位置 | 处理方式 |
| --- | --- | --- |
| `01-基本信息/` | `基本信息` | 维持原映射 |
| `02-内容创作/` 中从旧 `02-个人认知/` 迁来的文件 | `个人认知` | 在 `config/getnote-content-origin.json` 中按文件名查 |
| `02-内容创作/` 中从旧 `03-技术认知/` 迁来的文件 | `技术认知` | 在同一映射文件中查 |
| `03-信息记录/` 中从旧 `06-流水账/` 迁来的日期文件 | `GetSeek录音卡` | 仅保留历史归属；新条目需单独判断 |
| `03-信息记录/` 中从旧 `04-素材库/` 归入的条目 | `素材库` | 在 `config/material-migration.json` 中逐条查来源；Get 端未自动变更 |
| `05-主题资料/`（原 `05-信息记录/`） | `信息记录` | 本地仅改名，Get 端维持原知识库 |

`02-内容创作/` 的新稿件与 `03-信息记录/` 的新条目没有可靠的目录到知识库映射。尤其同一日期文件可能同时包含原 `GetSeek录音卡` 内容、原 `素材库` 内容、个人想法和待办；不要把整个文件按目录名默认同步到某一个知识库。若用户要同步，先明确条目、目标知识库、追加或覆盖方式，再进行外部操作。

## 同步检查

1. 确认本地源文件或 Get 端源笔记、目标位置与同步方向。
2. 比较标题、原文、来源和既有远端内容；同名不代表同一条资料。
3. 有冲突、批量移动或覆盖时先列出影响范围。
4. 执行后重新读取目标，核对内容及知识库归属。
5. Get 端未更新时，不把本地目录改名描述成“已同步”。
