# 来源原文同步

## 当前授权与范围

用户已确认原文同步样例，并授权替换旧的每日 Get 摘要与 AI 选题任务。每天 Asia/Shanghai 23:30 执行 Get → 本地的单向同步；没有新增或修改数据时不改信息记录。当前配置从 2026-10-07 开始，不回补更早的历史笔记。后续添加来源需要实现对应平台读取适配并明确授权范围。

运行前读取根目录 `AGENTS.md`，然后从固定项目根目录执行：

```bash
node cmd/cli.js record sync --source all
```

预览使用 `--dry-run`。预览会读取来源列表和详情，但不会下载附件、写入信息记录、保存来源快照或推进同步进度。

## 内容与存放

- `03-信息记录/YYYY-MM-DD.md`：日期按来源创建时间换算为 Asia/Shanghai，逐条保存原标题与来源元数据。Get 正文、引用内容、原始录音转写、其他录音转写、网页摘要和网页原文分别展示，非空字符串逐字符保留，包括首尾空白、错字、Markdown 与字面量 `\n`。
- `03-信息记录/索引.md`：每条来源记录一个链接；正文开头去除 Markdown 排版标记后，截取不超过 60 字作为检索摘录。源标签为空时使用明确标注的系统索引标签，不补造源标签。
- `outputs/信息同步/getnote/<原始ID>/<版本指纹>/`：完整详情响应 `raw.json`、附件副本和 `manifest.json`。所有响应字段都保存在原始 JSON 中；页面未逐项展开的空字段、标签 ID、章节与其他结构化数据仍可回查。
- `.zlx-cli/source-sync/`：进度、锁和事务暂存。此目录是运行数据，不能当作原始资料档案。

附件中的 link 类型保留原链接，不重新抓取网页；图片、音频、PDF、其他文件与正文 Markdown 图片下载为本地副本，但不改正文中的原链接。下载大小上限为单文件 256 MiB，失败或超限时停止本批，不假称附件齐全。缺失的源字段不能补写。来源已有的 AI 整理稿仍是来源内容，不当作用户已确认观点。

## 增量与更新

每次完整翻页，验证列表条数与来源总数一致；原始 ID 始终按字符串处理。以来源、凭证身份与原始 ID 管理进度，标题相同不合并。日期范围内的新增与修改都可补拉，因此漏跑后下次执行可以补齐，23:30 后产生的内容下一次写回原创建日期。

近期三天的记录还会重新取得详情，以接收平台延后生成的转写或正文。仅附件 URL 的短期签名变化不视为笔记编辑；保存的原始响应仍保留当时完整签名。较早记录依据完整列表的内容和元数据指纹判断变化。账号凭证发生变化时停止，先核对身份再处理进度，不能混用不同账号。

更新只替换自己的 `SOURCE_SYNC` 来源区块，保留旧原始版本、手写事项和区块外的备注。来源删除不联动删除本地历史。手动修改自动来源区块或来源索引区块后，后续来源更新会停下并报告冲突；将个人备注放在自动区块外更便于持续同步。

## 失败与核验

列表与详情 API 请求至少间隔 1.2 秒。网络、详情或附件失败会重试一次，仍失败则返回失败，不将其写成“没有笔记”。限流按接口或 HTTP Retry-After 指定时间重试，未指定时等待 10 秒；要求等待超过 60 秒、日配额或月配额耗尽、鉴权失败时停止本次。所有详情和附件取得后，才准备本地写入；提交前逐字符验证文本字段，并检查本地文件未发生变化。日期记录、索引和来源快照核验成功后，最后提交进度。

多文件写入发生中断时保留 `pending.json`，下一次正常执行先恢复，再读取来源。恢复遇到本地修改则停止，保留双方内容；不要自行删除 pending、状态或锁来绕过冲突。运行锁会自动识别并清理已退出进程留下的锁。

最终根据 CLI 返回的 `status` 和 `results` 报告结果：

- `synced`：简要报告新增、更新数量和日期文件路径；`recovered` 为 true 表示已恢复中断事务。
- `skipped`：没有新增或修改，保持安静，不额外创建或修改记录。
- 非零退出：报告实际失败或冲突，不声称成功，不展示密钥、原始响应、私密全文或附件签名。

定时任务只调用此命令，不能再生成原任务的摘要和视频选题。任务需要本机开机、桌面应用运行且项目可访问。
