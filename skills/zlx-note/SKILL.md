# zlx-note - 周某人笔记

## 项目根目录

本 Skill 的实际源目录位于 `<me-agent>/skills/zlx-note/`。从实际源目录向上两级定位 `me-agent`，先读取根目录 `AGENTS.md`。不要使用旧的 `~/clawd/project/me-agent/` 路径，也不要因为调用时的工作目录不同而把用户资料写进其他项目。

## 写入位置

| 用户意图 | 本地位置 |
| --- | --- |
| 查询或更新稳定的基本信息 | `01-基本信息/` |
| 整理已形成的个人或技术表达、文章或视频文字稿 | `02-内容创作/`，文件直接平铺 |

用户明确指定目标时以用户指定为准。原 `04-素材库/` 已归入按日记录；原 `05-信息记录/` 已改名为 `05-主题资料/`。新收到的普通信息统一按日记录；只有明确要求维护主题文档时才更新 `05-主题资料/`。外部资料和别人观点保留来源，不写成用户已经认可或亲自验证的观点。

## 记录一条信息

普通每日记录优先调用 `zlx-cli record add`；它会先追加日期文件，再更新索引。将原文写入临时 UTF-8 文件后执行：

```bash
zlx-cli record add --title "<标题>" --type "<类型>" --tags "标签1,标签2" \
  --summary "<不超过60字的摘要>" --content-file /tmp/record.txt
```

复杂旧格式或定点修改仍需按以下规则核对，不要让命令覆盖已有内容。

1. 以用户指定日期或 Asia/Shanghai 当前日期选择 `03-信息记录/YYYY-MM-DD.md`。
2. 检查当天文件是否存在；新建时写 `# YYYY-MM-DD`，存在时只追加或定点更新。
3. 每个独立事项使用可检索标题。新条目推荐 `## YYYYMMDD-序号 标题`，并按需写 `时间`、`类型`、`标签`、`来源链接` 和原始内容。已有旧文件无需整体改写。
4. 更新 `03-信息记录/索引.md`：月份和日期倒序，每天一条短概览，每个独立事项一条索引，列标题、类型、2～4 个标签和一句不超过 60 字的摘要。不要复制原文进索引。
5. 检查索引的相对链接能打开日期文件，摘要与原文一致。

参考 `references/templates/daily-journal.md`。候选选题先作为信息记录；用户要把它写成完整表达时，再在 `02-内容创作/` 建稿件并链接原记录。

## 查询资料

- 基本资料先查 `01-基本信息/`。
- 用户自己的已成形表达先查 `02-内容创作/`，按文件名和正文检索，不再限定“个人认知”或“技术认知”子目录。
- 普通记录先搜索 `03-信息记录/索引.md`，打开日期文件核对原文。索引未命中时全文搜索 `03-信息记录/`，再搜索 `05-主题资料/`。
- 可用 `zlx-cli record search "<关键词>"` 快速检索索引；命中后仍须打开日期文件核对原文。
- 列表展示按日期倒序。检索结果区分原文、外部引用和索引摘要。

## Get 笔记同步

只在用户要求时调用 `zlx-getnote` Skill 与 `zlx-cli getnote` 命令。先明确同步方向、目标笔记和覆盖范围；不得根据本地目录名自动猜测 Get 知识库。

- `01-基本信息/` 的既有知识库为 `基本信息`。
- `02-内容创作/` 中旧稿件的知识库归属见 `config/getnote-content-origin.json`。新稿件没有映射时需明确目标知识库。
- `03-信息记录/` 中从旧 `06-流水账/` 迁来的内容历史对应 `GetSeek录音卡`，从旧 `04-素材库/` 归入的条目历史对应 `素材库`；逐条来源见 `config/material-migration.json`。同一日期文件可能混合两类内容，不能整篇按路径自动同步。
- `05-主题资料/` 本地已改名，Get 笔记端仍使用原知识库 `信息记录`。

详见 `references/getnote.md`。本地资料整理不触发远端写入。
