### 1. Claude Code 插件到底新增了什么？答案可能不是能力

- **分类**：技术解释

- **核心判断**：插件的关键变化不是让 Agent 获得全新能力，而是为技能、代理、钩子和外部服务建立统一的打包、命名、加载与分发边界。
- **与 AI 的真实关系**：AI Agent 的能力常由提示词、工具、运行钩子和外部服务共同组成；没有标准封装，这些组件难以复用、升级、审计和安全治理。
- **内容框架**：
  1. 从“已经有 Skill，为什么还需要插件”这个现实疑问切入。
  2. 区分能力组件与分发容器：Skill、Agent、Hook、MCP 各自负责什么。
  3. 解释插件清单、命名空间和目录约定如何形成稳定边界。
  4. 对比独立 `.claude/` 配置与插件在加载、冲突和版本管理上的差异。
  5. 说明插件没有自动解决的事情：依赖、权限、兼容性和运行时安全。
  6. 落回结论：平台化的标志不是功能更多，而是能力可以被可靠交付。

### 2. 把 `.claude/` 工作流迁移成插件，最容易踩的六个坑

- **分类**：工程实践
- **关联笔记**：Claude Code 插件系统完全指南：从配置到发布的标准化之路
- **核心判断**：迁移不是简单复制目录；要先明确组件边界、命名冲突、外部依赖、加载方式和回滚策略，再用最小插件逐步验证。
- **与 AI 的真实关系**：Agent 插件会改变模型可见的技能、代理、工具和默认行为，错误的目录、依赖或优先级可能造成能力未加载、行为漂移甚至权限风险。
- **内容框架**：
  1. 选择一个已稳定运行的本地 Skill，定义迁移目标与不变行为。
  2. 建立最小目录：清单与能力组件分开放置，并确认命名空间。
  3. 逐类迁移技能、代理、钩子和 MCP，不一次性搬完全部配置。
  4. 排查覆盖关系、重复定义、二进制依赖和机器环境差异。
  5. 本地加载、热重载、严格校验，并为每个组件做可观察测试。
  6. 发布前固定版本、保留回滚路径，并按当前官方规则复核命令。
