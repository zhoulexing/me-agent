## AI 视频选题

### 选题 1：同一个 Agent，为什么不应该每一步都用最贵的模型？

- **分类**：技术解释
- **关联笔记**：AI Agent 降本增效新路径：OpenSquilla 0.5.0 开源项目深度测评与行业洞察
- **核心判断**：Agent 任务内部的步骤难度和风险并不相同。按整条查询固定一个模型，会让简单步骤浪费算力、关键步骤又缺少升级机制；真正有效的路由应进入执行过程，根据状态和反馈逐步决定模型。
- **与 AI 的关系**：它直接涉及多模型 Agent 的路由机制，也延续了“模型能力之外，Harness 决定任务表现”的技术判断。
- **内容框架**：
  1. 从成本反差开场：为什么一个长任务全程使用旗舰模型，可能既贵又没有更好？
  2. 解释查询级路由：任务开始前选一次模型，此后所有步骤都沿用。
  3. 解释步级路由：规划、搜索、写作、验证、错误恢复分别根据风险选择模型。
  4. 用“普通步骤走便宜模型，关键决策和失败恢复升级强模型”说明具体工作流。
  5. 说明代价：路由判断本身也会出错，多模型并行还会增加时延和系统复杂度。
  6. 得出结论：未来 Agent 降本的关键，不只是寻找更便宜的模型，而是让算力在正确的步骤出现。

### 选题 2：普通人的 AI 知识库，第一步不是分类，而是先让信息流进来

- **分类**：个人判断
- **关联笔记**：普通人构建知识库的简单方法
- **核心判断**：很多知识库失败，不是因为目录设计得不够专业，而是记录成本太高、输入无法持续。AI 时代更适合先建立低摩擦的收集入口，再让 AI 在需要时完成提取、关联和重组。
- **与 AI 的关系**：AI 降低了后期整理和召回成本，使“先收集、后组织”成为可行路径；但记录只有在更新认知或推动行动时才产生价值。
- **内容框架**：
  1. 从常见困境开场：很多人研究了很久知识库方法，却一条内容都没有真正留下。
  2. 解释为什么先做复杂目录会提高记录门槛，让系统在开始阶段就停摆。
  3. 给出最小流程：文章、语音、文件和想法先进入统一入口，只保留必要来源信息。
  4. 说明 AI 可以承担的工作：摘要、打标签、建立关联、按问题召回和定期复盘。
  5. 说明人的责任：判断什么值得保留、哪些观点属于自己、哪些内容应该转成行动。
  6. 得出结论：知识库不是收藏仓库，真正的闭环是输入数据、更新认知、推动行动。

### 选题 3：Claude Code 套上 GPT，真正替换的是模型，还是整个 Agent？

- **分类**：工程实践
- **关联笔记**：Claude Code 调用 GPT 5.6 Sol 简易配置方案全解析、Agnes-2.5-Pro
- **核心判断**：Agent 产品并不等于底层模型。模型、系统提示词、工具协议、上下文管理、代理层和运行时共同决定最终表现；把 Claude Code 的模型端替换为 GPT，只替换了其中一层，不能默认获得原生产品的完整行为。
- **与 AI 的关系**：它对应模型与 Agent Harness 的分层关系，也能帮助判断“换模型”类配置究竟改变了什么。
- **内容框架**：
  1. 从反直觉配置开场：为什么 Claude Code 可以被指向 GPT，名字没变，里面的模型却变了？
  2. 分层说明模型服务、代理 API、Agent CLI、工具层和本地执行环境。
  3. 解释模型替换后仍会保留哪些能力：外壳、工具协议、部分提示和工作流。
  4. 解释可能改变的部分：推理风格、工具选择、上下文处理、错误模式和计费方式。
  5. 列出验证清单：认证安全、工具兼容、长任务稳定性、模型名称真实性和平台规则。
  6. 得出结论：不要用产品名判断能力，要看模型和 Harness 的实际组合。
