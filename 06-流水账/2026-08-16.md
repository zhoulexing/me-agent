### 1. AI Agent 跑偏的根源：模型问题，还是状态机没设计好？

- **分类**：技术解释
- **关联笔记**：AI Agent长任务一致性与容错架构：高级工程师的三层核心认知

- **与 AI 的真实关系**：Agent 依赖模型动态决策，执行路径天然不确定；有限状态机、检查点和状态校验用于约束这种不确定性，直接决定长链路能否保持一致。
- **内容框架**：
  1. 从一个 Agent 执行十几步后悄悄偏离目标的真实问题切入。
  2. 区分计划、执行状态、业务状态和上下文记忆四个不同层次。
  3. 解释上下文压缩为什么可能丢失关键中间状态。
  4. 拆解有限状态机、检查点和断点回溯各自解决什么问题。
  5. 说明重试、重规划与人工接管的触发边界及成本差异。
  6. 落回结论：软件提供确定性骨架，模型负责在骨架内灵活决策。

### 2. 从“能跑通”到“敢上线”：生产级 Agent 的三层验收清单

- **分类**：工程实践
- **关联笔记**：AI Agent长任务一致性与容错架构：高级工程师的三层核心认知
- **核心判断**：生产级 Agent 不能靠一次成功演示验收，而要同时通过规划质量、执行容错和生产治理三层检查，并用可观测指标证明稳定性。
- **与 AI 的真实关系**：Agent 会自主选择工具和步骤，错误会沿长链路累积；只有把动态行为纳入准入、测试、监控、补偿和审批体系，才能安全放权。
- **内容框架**：
  1. 用“本地 Demo 成功一次”与“生产连续执行一万次”的差距建立冲突。
  2. 规划层验收：任务拆分、记忆压缩、缓存复用和关键状态保留。
  3. 执行层验收：完成率、一致性、准确率、平均步数和失败类型。
  4. 容错设计：原地重试、补偿事务、断点回溯、熔断与降级。
  5. 生产治理：工具准入、高危审批、步数并发红线、异常注入与监控。
  6. 给出可复用原则：先定义失败与验收，再决定 Agent 可以获得多少权限。

### 3. Agent 越聪明，为什么工程师越要假设它一定会失败？

- **分类**：个人判断
- **关联笔记**：AI Agent长任务一致性与容错架构：高级工程师的三层核心认知
- **核心判断**：真正成熟的 Agent 工程不是相信模型永不犯错，而是在默认它会遗漏、漂移和误判的前提下，仍让系统可停止、可恢复、可审计。
- **与 AI 的真实关系**：模型能力提升会扩大可委托任务范围，也会放大一次错误的影响半径；因此 AI 放权必须与边界、反馈、验收和恢复机制同步增长。
- **内容框架**：
  1. 从“模型更强以后，是不是可以少做工程约束”这个直觉切入。
  2. 指出长链路的乘法风险：单步小误差会在连续决策中不断累积。
  3. 讨论为什么只靠 Prompt 约束无法替代运行时状态校验。
  4. 用高危数据修改场景说明审批、熔断和回滚的必要性。
  5. 结合个人认知：AI 放权的前提是先搭出值得放权的框架。
  6. 给出行动判断：把“失败后怎么办”放到 Agent 方案设计的第一页。
