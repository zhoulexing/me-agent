# 个人写作方法论

## 一、核心流程

明确问题 → 研究问题 → 组织表达 → 检查打磨。

## 二、选题方法论

### 1. 选题来源

- **大公司 AI 招聘**：从岗位职责和能力要求中发现实际问题。
- **AI 人物**：从他们的观点、实践和产品中寻找选题。
- **AI 公众号**：从案例、争议和没讲透的地方寻找选题。
- **阅读书籍**：从原理、案例和跨领域联系中寻找灵感。

### 2. 选题提炼

#### 三步提问法

- **议题**：我想研究什么？
- **疑问**：关于它，我具体想弄清什么？
- **难题**：弄清这个问题，能帮助谁解决什么实际困惑？

例如：Agent 记忆 → 为什么保存了聊天记录，还是会忘记要求？→ 帮助开发者判断该保存什么、怎样让任务继续执行。

## 三、内容结构

### 1. SCQA：从冲突引出答案

S 是背景，C 是冲突，Q 是问题，A 是答案。先交代原有情况，再指出变化或矛盾，引出需要回答的问题，最后给出解释或方案。

例：Agent 能执行多步任务，但中途断线可能丢失进度。怎样避免从头再来？可以从任务状态、检查点和恢复策略展开。

### 2. 3W：把一个问题讲完整

What 是什么，Why 为什么，How 怎么做。适合解释概念、分析原因和介绍方法。

例：什么是上下文压缩？为什么 Agent 需要它？压缩时怎样保留目标、约束和未完成事项？

### 3. 三幕剧：用变化推动故事

开端建立人物、目标和处境；中段通过冲突与尝试推动变化；结尾呈现结果和认识。适合讲亲身经历、项目实践和探索过程。

例：想让 Agent 自动分析问题 → 实践中遇到信息缺失、重复执行，逐步改进 → 总结哪些环节仍需人工判断。

### 4. 三段式：开头、主体、结尾

开头交代问题或观点，主体展开解释和论证，结尾回答问题、总结判断。适合短视频和短文章，不要求有故事情节。

例：开头提出“工具调用成功不等于任务完成” → 主体区分接口成功与业务结果正确 → 结尾强调验收最终状态。

### 5. 比较式：在差异中说明选择

围绕同一个问题，用一致的维度比较不同方案，说明各自适用条件。

例：比较单 Agent 与多 Agent，从任务独立性、协调成本和结果验收三个维度，说明什么时候值得并行。

### 6. 分类式：把复杂问题拆开讲

按明确标准划分问题，分别解释各类的特点与处理方式。

例：把 Agent 失败分为理解错误、工具错误、环境故障和验收遗漏，分别讨论如何定位。

### 7. 递进式：从现象走向机制

沿一条主线逐层深入，让前一层解释成为后一层的基础。

例：Agent 为什么会忘事？→ 哪些信息没有进入当前上下文？→ 信息怎样被筛选和压缩？→ 怎样设计更可靠的状态保存机制？

## 四、表达原则与技巧

- **对象感**：明确在对谁说，根据对方已有的知识和困惑安排信息。
- **逻辑势能**：回答一个问题后，自然引出下一问，推动读者继续理解。
- **判断与依据**：结论有证据，推理不跳步，交代适用条件和边界。
- **故事**：呈现事情怎样发生、人物怎样改变。
- **例子**：把抽象概念落到具体情境。
- **比方**：借熟悉的事物建立理解，注意类比的边界。
- **金句**：用简洁的话收住已经讲清楚的意思。
- **检查打磨**：先查观点和依据，再查结构，最后修措辞和节奏。
