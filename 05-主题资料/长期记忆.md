# 长期记忆

## 一、长期记忆分类

- **会话记忆**：保存聊过什么，包括原始对话和摘要。例如，一次需求讨论的对话及最终约定。
- **语义记忆**：保存事实、概念和偏好。例如，用户偏好简洁的中文回答。语义记忆是内容类型，语义搜索是检索方式。
- **情景记忆**：保存一次事件的背景、过程和结果。例如，某次部署失败的原因、排查过程和解决结果。
- **程序记忆**：保存可复用的方法、流程和技能。例如，发布前的检查步骤。

会话是来源载体，可以包含另外三种内容，四类不是互斥的桶。对话记录需持久保存并可跨会话访问，才能成为长期记忆来源；当前上下文不等于长期记忆。语义、情景和程序的分类参考 [LangChain 官方说明](https://docs.langchain.com/oss/python/concepts/memory)。

## 二、长期记忆怎么做

### 1. 怎么存

保存稳定且有复用价值的事实、偏好、约定、经历和方法，附上来源、时间、适用范围与可靠程度，区分用户确认、外部观点和推测。

写入有三种方式：用户明确要求记住；Agent 在任务中主动判断并保存；后台从历史中提炼。后两种也要遵守写入范围，不能把助手推断当成用户确认。

写入时查重、纠错，处理冲突与过期；凭证不存，临时事实按有效期处理。

### 2. 怎么取

- **提示词引导**：在 system 中说明存什么、存哪里、何时读，Agent 按任务通过工具查记忆。
- **核心索引引导**：把目录、主题摘要和关键线索放入上下文，Agent 按索引读取细节。
- **Query 自动召回**：程序每次收到用户输入，按 query 检索记忆，再注入上下文。
- **混合召回**：先自动召回少量；信息不足时，Agent 根据提示词和索引补查。

### 3. 取完怎样筛选和使用

先按权限硬过滤，再看相关性、来源可靠性、时效性、重要性、上下文预算与冲突：是否解决当前问题，信息是否可信且仍有效，是否值得占用上下文，有无相反记录。当前明确更正优先于旧记忆。

检索 score 表示检索匹配程度；记忆质量看真实性、来源与时效；使用优先级看当前任务需求。三者不能混为一谈，应用侧分数也不是模型内部注意力权重。

### 4. 更新与遗忘

更正错误、合并重复、归档过时内容，按要求删除不应继续保留的记忆。正文、摘要、索引及检索副本保持一致，避免旧信息继续被召回。保留来源与修订关系，不把反复生成的同一判断当成新增证据，防止错误被持续强化。

## 三、开源框架

### Mem0

记忆组件，通过 `add` 提炼保存、`search` 检索。官方基础示例由应用先搜索，再放入 system，最后调用模型；也可在外层封装工具，让模型按需查。核心库不默认监听用户输入。可选 OpenClaw 插件支持自动召回加主动补查；开源组件与 Mem0 Platform 托管服务要分开看。[官方仓库](https://github.com/mem0ai/mem0)、[插件召回规则](https://github.com/mem0ai/mem0/blob/main/integrations/openclaw/skill-loader.ts)。

### Hindsight

可自托管的专用记忆服务：`retain` 保存，`recall` 检索，`reflect` 基于记忆综合推理。OpenAI Agents 工具模式由应用绑定 `bank_id`，模型填写 query，提示词要求回答前查；实际调用仍由模型决定。[官方仓库](https://github.com/vectorize-io/hindsight)、[Agents 集成](https://hindsight.vectorize.io/sdks/integrations/openai-agents)。

可选 `memory_instructions` 每轮动态注入，但默认用固定 query，不默认读取当轮输入；LiteLLM wrapper 在未指定 query 时默认用最后一条用户消息。服务能力和集成策略不能混同。[LiteLLM 集成](https://hindsight.vectorize.io/sdks/integrations/litellm)。

### Letta Code

完整 Agent 框架，当前以 MemFS 保存 Markdown 记忆。根部核心内容和目录索引常驻上下文，详细文件按需用 Read、grep 等工具读取；提示词引导 Agent 遇到不熟悉的人、项目或概念时查记忆。默认不带向量索引，检索依赖文件组织和模型主动查找；不宜沿用旧 archival API 描述当前机制。[官方仓库](https://github.com/letta-ai/letta-code)、[MemFS 文档](https://docs.letta.com/concepts/memfs)。

### Graphiti

增量构建带时间信息的知识图谱，保存实体、关系事实及来源事件，结合语义、关键词与图搜索。核心检索由调用者提供 query；接入 MCP 工具并配客户端规则，可让模型主动查。库本身不自动监听输入，图谱运营仍需应用配合；Graphiti 不等于整个 Zep 托管平台。[官方仓库](https://github.com/getzep/graphiti)。

### LangGraph

提供 checkpointer 保存线程状态、Store 保存跨线程记忆。官方示例由开发者在节点中明确执行搜索并构建模型消息，也可接工具按需查；何时写、何时读由应用或模型策略决定，没有统一默认自动召回策略。线程恢复与跨线程记忆是不同职责，业务规则仍需开发者设计。[官方文档](https://docs.langchain.com/oss/python/langgraph/add-memory)。

### EverOS

本地优先的记忆组件与服务，原名 EverMemOS，以 Markdown 为内容原本，SQLite 管状态，LanceDB 提供全文和向量检索；直接修改受支持格式的记忆文件后，文件监测器会同步索引。`/memory/add` 累积输入并在话题边界触发提取，`/memory/flush` 强制提取会话尾部，`/memory/search` 接收调用者提供的 query；核心服务本身不监听宿主聊天，也不自动注入模型上下文。[官方仓库](https://github.com/EverMind-AI/EverOS)、[记忆流程](https://github.com/EverMind-AI/EverOS/blob/main/docs/how-memory-works.md)。

用户记忆包含情景、事实、前瞻与画像；Agent 记忆包含执行案例及从案例中提炼的 `SKILL.md`。后台引擎异步更新派生记忆，Reflection 可合并相关情景，但默认关闭；这里的自进化是更新外部记忆与技能，不是训练模型参数。技能提炼已有实现，但技能退役尚未完整实现，不能把自动积累等同于持续纠错。[技能提炼源码](https://github.com/EverMind-AI/EverOS/blob/main/src/everos/memory/strategies/extract_agent_skill.py)。

可选 OpenClaw 插件在回复前按用户输入自动检索并注入历史上下文，回复后保存对话与工具轨迹，会话结束时 flush；这是插件策略，不是核心库的默认行为。插件占用独占 memory 槽、替换默认 `memory-core`，需要授予会话访问权限；后端不可用时聊天继续，记忆功能暂停。[OpenClaw 插件](https://github.com/EverMind-AI/plugins/tree/main/openclaw)。

写入与检索为最终一致，刚提取的记忆不保证立即可搜到。基础提取与关键词检索需要 LLM；向量检索、Reflection 和技能提炼还需 embedding，部分高级检索需 rerank。本地优先指存储架构，不代表配置云端模型后内容仍完全留在本机；服务默认面向可信本地调用，多用户权限不能仅依赖检索范围参数。现有 Markdown 资料库也不能未经格式适配就视为可直接接管。以上按 2026-10-15 的 1.4.2 资料及部分源码整理，未运行验证。[安全边界](https://github.com/EverMind-AI/EverOS/blob/main/SECURITY.md)。
