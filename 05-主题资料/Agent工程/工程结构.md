# Agent Harness 工程结构

目标是在 `projects/agent-harness/` 从零实现一套可运行、可验证、可用于讲解的 Agent Harness。以下是目标结构，目录随实际开发逐步建立；当前文档不表示对应代码已经实现。

## 目录

```text
projects/agent-harness/
├── apps/
│   └── cli/                    # 唯一可执行入口：交互运行、单次运行、启动 Server
├── packages/
│   ├── core/
│   │   ├── agent/              # Agent 对外契约、状态与事件
│   │   ├── agent-loop/         # 轮次与步骤驱动；ReAct 等策略在此实现
│   │   ├── session/            # 会话、轮次与事件日志
│   │   └── tools/              # 工具注册、调用与结果处理
│   ├── llm/                    # 模型调用契约与具体模型适配器
│   ├── context/                # 提示词组装、上下文选择与压缩
│   ├── governance/             # 权限、审批、取消、预算与审计
│   ├── execution/              # 文件、命令、沙箱等本地执行能力
│   ├── persistence/            # 会话持久化与恢复
│   ├── sdk/
│   │   ├── protocol/           # JSON-RPC 方法、数据类型、错误和事件
│   │   ├── server/             # stdio JSON-RPC Server，映射协议与 Harness
│   │   └── client/             # 外部程序调用时再实现
│   └── runtime/                # 用普通代码组装上述模块，提供统一 Harness 接口
├── examples/                   # 按学习阶段演进的可运行案例
├── tests/                      # 跨模块、CLI 与协议边界的测试
└── README.md                   # 运行方法与工程入口
```

借鉴 DeepSeek Harness 的 `apps/` 与 `packages/` 分工：`apps/` 放可执行入口，`packages/` 按能力组织。这里不引入它的插件框架、Bundle 配置或 Profile 机制；`runtime/` 用显式代码完成依赖装配。某个能力需要独立契约或可替换实现时，再把它拆成更细的包，避免一开始创建大量空包。

## 运行边界

```text
CLI run ───────────────┐
                      ├─→ runtime → Agent Loop → 模型 / 工具 / 会话状态
CLI server → SDK Server┘
                 ↑
          JSON-RPC Protocol
```

- `apps/cli/` 负责命令解析与进程生命周期。单次运行和 `server --stdio` 均调用同一个 `runtime/`，不各自实现 Agent Loop。
- `core/` 定义 Agent 的执行主干；ReAct 是 `agent-loop/` 中的一种策略，不作为整个工程的顶层架构。
- `sdk/protocol/` 只定义进程间契约；`sdk/server/` 负责传输、校验、调用映射和事件推送，不持有另一套会话状态。
- Server 首先使用 stdio 上的逐行 JSON-RPC。标准输出只发送协议消息，诊断信息走标准错误。优先定义初始化、创建或恢复会话、开始或取消轮次、审批响应及进度事件；请求被接收与轮次完成分别表达。
- `governance/` 控制工具是否可执行，`execution/` 实际执行，`persistence/` 保留可恢复的事实；这些边界同时服务 CLI 与 Server。

## 从零到一的顺序

1. **最小闭环**：模型接口、Agent Loop、会话事件、一个受控工具和 CLI 单次运行。
2. **可靠运行**：权限与审批、取消、工具输出边界、会话持久化和恢复。
3. **对外接口**：JSON-RPC 协议与 stdio Server；用同一案例核对 CLI 和 Server 的行为。
4. **体系完善**：上下文压缩、更多工具和模型适配器、观测与评测；确有外部调用需求时增加 SDK Client。

每一步在 `examples/` 留下可运行案例，课程内容可据此解释问题、设计取舍、代码实现和验证结果。工程仓库的 README 记录实际运行方式；本主题目录继续保存原理研究与课程材料。
