### 🔍 为什么需要 dsh-context？

DSH 长任务**上下文占用明细不透明**，出问题只能事后翻记录。
- **痛点**：界面只显示总占用，系统提示、工具 schema、工具返回、注入内容各占多少看不到
- **定位**：DeepSeek Harness 的**开源插件**，把上下文组成、变化、压缩/剪枝过程全部可视化

### 📍 有哪几个查看入口？

一共 **4 个入口**，适用场景各不同。

| 入口 | 适用场景 |
| :--- | :--- |
| Context 标签页 | 查看当前单会话详情 |
| Context Insights 页面 | 跨会话看一段时间总用量 |
| 右侧栏 Context 面板 | （原文未单独说明） |
| `/context` 命令 | 聊天中临时弹窗查看当前组成 |

### 📊 跨会话用量能看到什么？

**Context Insights** 汇总所有会话的用量与成本。
- **核心指标**：会话数、计费 token、估算费用、**缓存命中率**、工具调用次数、活跃时长
- **可视化**：最近 7 天用量柱状图 + 近几周活动热力图
- **会话卡片**：每个会话带上下文组成环、token 数、轮次、估算费用
  - 支持按最近时间 / token 量 / 上下文大小排序
  - 支持按工作区分组
- **费用说明**：按 models.dev 目录价估算，已计入 DeepSeek 峰谷价，**仅作参考**

### 📑 单个会话的 Context 页面有什么？

单会话数据**集中在一页**，不用来回切换。
- **顶部统计**：轮次、步数、工具调用次数、缓存命中率、token 去向占比、时间分配
- **数据一致性**：占用率与组成和 DSH 官方 token meter 用**同一组投影数据**，与输入框旁的上下文环数字一致
- **下方模块**：当前窗口、上下文趋势、Context Browser、事件、文件活动、Agent 网络

### 📏 当前窗口组成怎么看？

用**多色堆叠条**展示 6 类内容的占比。
- **6 类组成**：系统提示、工具 schema、用户消息、注入内容、助手回复、工具结果
- **剩余空间**：用斜纹标识
- **实用提示**：上下文不够用时，**工具定义和工具结果**通常占大头，不一定是用户输入过多
- **精度说明**：分类数字为 DSH 固定密度启发式估算，非精确测量；钉住某一步后，provider 上报的实际 prompt / output / cache 数字更可靠

### 📈 上下文变化趋势怎么看？

**Context Trend** 按每次模型请求画堆叠条，粒度更细。
- **粒度切换**：支持 Step（步）或 Turn（轮）两种粒度
- **查看模式**：Total（总量） / Delta（增量）
  - Delta 模式：增长堆在基线上方，压缩往下掉，长会话压缩次数一目了然
- **Step 摘要**：图下方显示用户输入、新增上下文内容、模型回复/工具调用
- **压缩标记**：压缩和剪枝标在对应柱子上，可看到回收 token 数

### 🗂️ Context Browser 能查到多细？

可展开查看**每次请求的完整组成内容**。
- **可展开项**：
  - 系统提示 → 看原文
  - 工具 → 看 JSON schema
  - 消息 → 看正文
  - 工具结果 → 看参数、状态、返回值
  - 助手回复 → 可按 Thinking / Tools / Answer 筛选
  - 图片 → 卡片展示缩略图、尺寸、存储大小、DeepSeek 图像 token 估算
- **工具来源标记**：标注官方 `tool-*` 包、`dsh-*` 能力包、MCP server、插件注册工具
- **轮次 diff**：与上一轮对比，增减 token 数用徽标标出
- **注意**：压缩前步骤从被移除消息归档重建，界面标"近似"，仅作参考

### 📁 文件活动和 Agent 网络有什么用？

分别展示**文件操作轨迹**和**多 Agent 关系**。
- **File Activity**：
  - 分类：读 / 写 / 搜索路径 / 处理图片
  - 写操作估算新增/删除行数，点开可看完整操作记录，跳回对应工具结果
- **Agent Network**：
  - 展示主 Agent、父级 Agent、所有子 Agent 的关系
  - 每个节点对应一个会话，环大小按窗口占用缩放
  - 悬停看 token、请求数、费用、活跃时间，点击跳转对应会话 Context 页
  - 适合多 Agent 会话快速排查各 Agent 占用情况

### 🛠️ 怎么安装？

两种方式，**无需手动构建和额外重启**。
- **界面安装**：DSH Web/桌面端 → Add plugin → 搜索 `dsh-context` → Install
- **命令行安装**：
  ```
  dsh plugin --profile web add dsh-context
  ```
- **更新命令**：
  ```
  dsh plugin --profile web update dsh-context@latest
  ```
- **启动**：装完用 `dsh web` 启动 Web UI

### ⚠️ 兼容性和注意事项？

有明确的版本要求，且插件**只观测不干预**。
- **兼容版本**：
  - DSH：`@deepseek-ai/dsh` 0.1.5-rc.1、0.1.7-rc.2、0.2.0-rc.2
  - Node：`^22.19.0` 或 `>=24.0.0`
  - 旧版本建议先升级 DSH
- **能力边界**：
  - ✅ 观测、定位、回看上下文
  - ❌ 不会主动删上下文
  - ❌ 不会替你决定何时压缩
  - 省 token 仍需从工具数量、提示词、注入内容、任务拆分入手
- **安全提醒**：插件是本机运行的第三方代码，安装前建议检查源码、依赖、仓库活跃度

### 🎯 适合哪些场景？

**长会话、多工具、多 Agent** 场景价值最大。
- 偶尔短聊 → 差别不大
- 长会话 + 多工具 + 多插件 + 多 Agent → 信息增益明显
- 定位：**排查工具**，不改模型、不省 token，只把上下文明细摊开供判断

GitHub：`https://github.com/bowenliang123/dsh-context`

平时用 DSH 跑长一点的任务，上下文窗口里会不断塞进系统提示、工具
schema、工具返回和各种注入内容。界面通常只告诉我们占用了多少，具体是哪一部分占了，就不太容易看出来。等到压缩发生，再回头找原因，基本只能去翻记录。

dsh-context 主要就是把这些内容展示出来。它是 DeepSeek Harness
的一个开源插件。装上它，一次会话的上下文由什么组成、后来怎么变、什么时候压缩或剪枝，都能直接看。

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2F26875e010f7cd1130d84b1daaf0c3486?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=62xvv3%2B6%2BfKGFZJjduwYWqkwaG8%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

让 AI Agent 的上下文生命周期完全可视化，随时可以看，我感觉可以让我使用 DSH 的体验上升一个档次，今天我们来聊聊这个开源项目。

# 它能看什么

dsh-context 现在有几个查看入口：跨会话的 Context Insights 页面、单个会话里的 Context 标签页、右侧栏的 Context
面板，还有聊天里的 `/context` 命令。这几个入口有重合，区别在什么时候用。

平常看当前会话，用 Context 标签页就够了。要看最近一段时间所有会话的用量，可以打开 Context Insights。`/context`
会打开一个弹窗，适合在聊天过程中临时看一眼当前组成。

### 跨会话用量

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2F2386fccd00a461024b7b9c5e59f939b0?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=cSHJ1Td3XJbaMp1ARQj30R0TPIk%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

Context Insights 看的是一段时间内所有会话的情况。这块会列出会话数、计费 token、估算费用、缓存命中率，还有最近 7
天的用量柱状图和近几周的活动热力图。

拉到底，下面的会话卡片信息更具体。每个会话都有自己的上下文组成环、token
数、轮次和估算费用，可以按最近时间、token、上下文大小排序，也可以按工作区分组。会话比较多的时候，先看这里会方便一些，不用一个个点进去找。

费用这块不一定绝对精准，它是按 models.dev 的目录价估算出来的，虽然把 DeepSeek 的峰谷价也算进去了，但也就是看个大方向。

### 单个会话的 Context 页面

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2Fa3a1eb840a5d23d3a411df9f299e8455?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=2G3NGsmWfRl7X3qvRYpNyPqBiGE%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

单个会话里的 Context 标签页内容更全。上半部分是轮次、步数、工具调用、缓存命中率、token
去向和时间分配；往下还有当前窗口、趋势、浏览器、事件、文件活动和 Agent 网络。

这些数据放在同一页，看的时候不用在几个地方来回切换。token 花在哪、时间耗在模型还是工具上，在这一页就都能看全。

面板头部的占用率和组成，用的是 DSH 官方 token meter
的同一组投影数据，所以和输入框旁边的上下文环对得上。这样插件和原界面至少不会各显示一套数字。

### 当前窗口的组成

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2F0d6f3211f738f33d680dfc036621fa85?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=RCwO44IF1tOecxN4sZbaytWy6IQ%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

Current Context 这张卡比较直观。它用一条多色堆叠条展示当前上下文窗口：系统提示、工具
schema、用户消息、注入内容、助手回复、工具结果分别占了多少，剩余空间用斜纹表示。

上下文不够用得时候，工具定义和工具结果经常会占掉很大一部分，不一定是我们自己输入的内容太多。dsh-context
会把这些内容分开列出来，还会标出占用最高的工具 schema。插件和工具比较多的会话，可以先看这部分。

不过这里的分类数字还是估算值。它用的是 DSH 自己的固定密度启发式，不能当成精确测量。钉住某一步以后，面板会把 provider 上报的实际
prompt、output、cache 数字放在估算值旁边。需要准确数字的话，provider 上报的那部分更可靠。

话说回来，这类如果像精准，只能官方出工具直接调后台，否则一律会有细微差别。

### 上下文变化趋势

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2F3a59b663af9dcd5a967ec75eed38cf7b?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=U%2Bl9NVvWhg9K5XJsXFTvf8sXiBs%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

Context Trend 会把每次模型请求画成一根堆叠条，可以切成 Step 或 Turn
粒度，也可以看总量或增量。一轮对话里可能有多次模型调用，每次调用带进去的上下文也不一样，所以它比只看消息列表更细。

趋势图下面还有一段简短的 step
摘要，会写出用户发了什么、新进入上下文的内容是什么、模型回复或调用了什么工具。压缩和剪枝会标在对应的柱子上，上下文在哪一步变小，也能看到回收了多少。

切到 Delta 模式后，增长会堆在基线上方，压缩会往下掉。长会话里发生过几次压缩，看这张图基本能对上位置。

### Context Browser

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2Fdf05b4704913146281006fe1781f3a19?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=A8qMWeOAnCkw8kh6eqeu1UauHBI%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

Context Browser 可以打开保留下来的请求，查看那次请求实际由哪些内容组成。

每个分类都能继续展开。系统提示可以看原文，工具可以看 JSON schema，消息可以看正文，工具结果可以看参数、状态和返回值。助手回复还能按 Thinking
/ Tools / Answer 筛选。图片内容会以卡片形式展示，包含缩略图、尺寸、存储大小和 DeepSeek 的图像 token 估算。

工具 schema 这一栏会尽量标出工具来源，比如官方 `tool-*` 包、`dsh-*` 能力包、某个 MCP
server，或者某个插件注册的工具。工具多的时候，这个来源标记能帮我们确认每个工具来自哪里。

它也能和上一轮做 diff。哪一类多了几条、多了多少 token，会用增减徽标标出来。压缩前的步骤是从被移除消息的归档里重建的，界面会标“近似”，只能当参考。

### 文件活动和 Agent 网络

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2F7f23791b86d1f369354f8ed77eb0e849?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=LBCEocC88z6hZ%2FbxtIGTcJ%2Fg%2BS8%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

File Activity 会按文件列出 Agent
的操作：读过哪些文件、写过哪些文件、搜过哪些路径、处理过哪些图片。写操作会估算新增和删除的行数，点开一行还能看到完整操作记录，并跳回 Context
Browser 里对应的工具结果。

除了上下文占用，这里也能看到文件操作过程。比自己翻一整串工具调用方便一些。

![图片](https://get-notes.umiwi.com/morphling%2Fvoicenotes%2Fprod%2F6b5cb7547978be60c7bcef4b8d58452d?Expires=1794065571&OSSAccessKeyId=LTAI5t7toTp72R3TvdXf9QdK&Signature=QPnJzLIFP4HKdNcbAX72w2G0Q%2Fg%3D&x-oss-process=image%2Fresize%2Cm_lfit%2Cw_720%2Ch_3240)

Agent Network 用来展示主 Agent、父级 Agent 和所有子 Agent。每个节点对应一个会话，环的大小按窗口占用缩放，悬停能看
token、请求数、费用和活跃时间，点进去可以跳到对应会话的 Context 标签页。多 Agent 会话里，可以用它先看各个 Agent 的占用和调用关系。

# 安装方式

README 里给了两种安装方式。

在 DeepSeek Harness Web 或桌面端里，打开 Add plugin，搜索 `dsh-context`，点击 Install。

命令行方式是这样：

```
dsh plugin --profile web add dsh-context
```

更新命令：

```
dsh plugin --profile web update dsh-context@latest
```

装完用 `dsh web` 启动 Web UI。README 写的是不需要手动构建，也不需要额外重启。

兼容性别踩坑：

> 当前仓库的兼容矩阵覆盖 `@deepseek-ai/dsh` 0.1.5-rc.1、0.1.7-rc.2、0.2.0-rc.2 这几条版本线；包本身要求
> Node `^22.19.0` 或 `>=24.0.0`。如果还在更旧的 DSH 版本上，建议先升级。

插件是本机跑的第三方代码，装之前最好翻翻源码、依赖，看看仓库还活不活跃。这个提醒不只针对 dsh-context，其他 DSH 插件也一样。

# 容易误读的地方

README 里用到了 management，但从目前公开文档看，dsh-context
的主要能力是观测、定位和回看。它不会主动删上下文，也不会替你决定什么时候压缩。真想省上下文，还是得从工具数量、提示词、注入内容和任务拆分下手。

# 适合哪些情况

偶尔用 DSH 聊几句，装不装这个插件差别不大。长会话、多工具、多插件、多 Agent 的场景里，它能提供的信息会多一些。

我更愿意把它当排查工具用，它不改模型，也不负责帮你省 token。它只负责把上下文组成、变化过程、文件操作和 Agent 关系摊开，怎么处理还得看项目。

真出问题时，至少有明细可查。
