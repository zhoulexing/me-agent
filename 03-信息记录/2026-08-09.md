## AI 视频选题

### 1. Agent 插件标准化，到底标准了什么？

- **分类**：技术解释
- **关联笔记**：Agent Plugins 1.0.0 规范深度解读：AI Agent 插件标准化时代开启
- **核心判断**：插件规范真正降低的是分发和发现成本，而不是能力开发成本，更不是安全治理成本。统一目录、元数据与 MCP 入口，可以让客户端知道“包里有什么、从哪里加载”，却不能保证能力可靠、权限合理或凭据安全。
- **与 AI 的真实关系**：Agent 的能力越来越依赖 Skill、MCP 和外部工具。缺少统一包装时，每个客户端都要重复适配；标准包装形成后，生态更容易流动，但模型的不确定性、工具权限和运行时隔离仍需客户端用确定性机制约束。
- **内容框架**：
  1. 从开发者痛点切入：同一个 Skill 和 MCP，为什么过去要为不同客户端重复打包？
  2. 用“包装盒”类比三层结构：plugin.json 说明身份，skills/ 暴露能力，mcp.json 连接工具。
  3. 解释目录即发现与局部失败隔离，说明标准如何降低客户端适配和插件分发摩擦。
  4. 明确没有标准化的部分：Skill 内容、MCP 协议本身、安装流程、权限、签名和密钥管理。
  5. 结合工程边界讨论：插件可移植不等于可信任，运行前仍需来源校验、最小权限和沙箱隔离。
  6. 给出结论：这是 Agent 生态的包格式起点，不是安全标准，更不是插件能力质量认证。

### 2. 多个 AI 能互相发消息，就等于会协作了吗？

- **分类**：工程实践
- **关联笔记**：Anthropic Claude Code 跨会话消息功能详解：多 AI 智能体协同时代到来
- **核心判断**：跨会话消息只解决了协作系统的传输层，真正决定多 Agent 是否有效的，是任务边界、共享状态、冲突处理、验收证据和最终责任人。没有这些协议，消息越多，协调成本反而可能越高。
- **与 AI 的真实关系**：多个代码 Agent 可以并行调查、编码和测试，但各自上下文不同，容易重复劳动或沿错误假设继续执行。ListAgents、SendMessage 一类原语让信息流动成为可能，却仍需确定性的任务编排和校验机制来管理模型的不确定行为。
- **内容框架**：
  1. 从真实场景开场：前端、后端、测试三个 AI 同时工作，为何最后仍可能合并失败？
  2. 分层解释协作系统：消息传输、共享状态、任务分配、冲突消解、结果验证与责任归属。
  3. 说明跨会话消息解决了什么：减少复制粘贴、支持进度通知、阻塞求助和结论移交。
  4. 说明它没解决什么：发送时机、信息可信度、修改冲突、上下文污染和谁来验收。
  5. 给出工程方案：每个任务明确输入输出，消息携带证据和影响范围，主会话统一验收与合并。
  6. 总结可复用原则：先设计协作协议，再增加 Agent 数量；连接能力不是组织能力。

### 3. AI 不是许愿池：做 AI 工具之前，先把问题诊断清楚

- **分类**：个人判断
- **关联笔记**：从公众号看到的两点关于AI与坚持的启发
- **核心判断**：多数 AI 项目失败，不是模型不够强，而是人把目标、原因和约束混在一句愿望里。真正重要的第一步不是生成方案，而是找到可验证的问题；真正能坚持的第二步，也不是加大意志力，而是把第一次行动缩到足够小。
- **与 AI 的真实关系**：模型擅长补全表达和生成可能方案，因此会把模糊需求包装得很完整；如果业务诊断错误，它只会更快放大错误方向。反过来，明确指标、原因假设和最小实验后，AI 才能成为分析与执行的能力放大器。
- **内容框架**：
  1. 用“做一个 AI 工具提升复购率”开场，追问复购率低到底发生在哪个用户环节。
  2. 拆开愿望与问题：愿望描述想要什么，问题需要现象、原因假设、约束和验证标准。
  3. 解释 AI 的语言优势为何会制造完成幻觉：方案很完整，不代表诊断是对的。
  4. 给出四步方法：观察数据、提出原因、设计最小实验、再让 AI 生成或执行具体动作。
  5. 把“最小开始”接入工作流：让第一步十五分钟内可完成，并留下可反馈的结果。
  6. 收束个人判断：AI 能放大行动，但问题定义和是否开始，仍然是人的责任。

### 4. AI 学习助手最该做的，不是总结，而是帮你找到知识枢纽

- **分类**：个人判断
- **关联笔记**：北大团队研究发现：高效学习的关键在于压缩学习与枢纽优先；从公众号看到的两点关于AI与坚持的启发
- **核心判断**：AI 总结降低了信息压缩成本，但学习效果不取决于摘要有多短，而取决于是否先建立能连接后续细节的核心框架。没有学习目标与枢纽选择，AI 只会把碎片压成更短的碎片。
- **与 AI 的真实关系**：大模型可以从材料中提取概念、关系和前置依赖，辅助生成知识地图；但哪些节点对当前目标最关键、是否真正理解、能否迁移到任务中，仍需学习者通过提问、实践和验收来判断。相关研究依据尚未核验，选题需进一步研究。
- **内容框架**：
  1. 从常见困境切入：让 AI 总结了十篇文章，为什么脑中仍然没有一张可用的地图？
  2. 区分信息压缩与认知建模：前者减少字数，后者建立概念之间的因果、层级和依赖。
  3. 解释“枢纽优先”的直觉：先学能解释最多现象的节点，再用细节修正和扩展框架。
  4. 给出 AI 用法：让模型列核心概念、前置依赖、典型反例和可验证任务，而不只生成摘要。
  5. 设计一次学习实验：围绕真实项目选三个枢纽，每个用输出或实践题检查是否掌握。
  6. 结尾落回边界：AI 可以帮你画地图，但学习路线的目标和验收仍需自己承担。
