- **分类**：技术解释
- **关联笔记**：Codex SDK 与 Agents SDK 区别及选型调研
- **核心判断**：区分两个 SDK 不应只对照功能表，关键要看开发者是在自行设计通用 Agent Loop，还是嵌入一套面向编程任务的完整 Agent 运行时。
- **与 AI 的真实关系**：Agent Loop 决定模型如何接收上下文、选择工具、处理反馈和终止任务；谁拥有这层控制权，直接影响可定制性、可靠性与集成成本。
- **内容框架**：
  1. 从“两个 SDK 都能调用模型和工具，为什么还要分开”切入。
  2. 先拆三层：基础模型 API、Agent 编排、编程 Agent 运行时。
  3. 解释通用 Agent Loop 中状态、工具、移交和追踪的职责。
  4. 解释编程 Agent 运行时为何还要管理代码执行、线程、审批与事件流。
  5. 指出笔记中的层级关系只是待验证假设，不能直接视为实现继承关系。
  6. 给出判断方法：先确认自己要控制哪一层，再讨论具体 SDK。

### 2. 给内部研发平台接入 AI 编程能力，应该怎么选 SDK？

- **分类**：工程实践
- **关联笔记**：Codex SDK 与 Agents SDK 区别及选型调研
- **核心判断**：SDK 选型应从真实任务、运行边界和验收方式倒推，而不是选择功能最多的框架；编程执行与通用业务编排可以拆成两个职责明确的组件。
- **与 AI 的真实关系**：AI 编程任务涉及代码库访问、命令执行、长任务恢复、人工审批和结果验证，这些运行时要求与普通问答 Agent 的工具编排有本质差异。
- **内容框架**：
  1. 设定真实任务：在内部平台完成代码审查、修复并提交可验证结果。
  2. 列出边界：仓库权限、沙箱、会话状态、审批、审计和失败恢复。
  3. 判断哪些能力由现有平台提供，哪些必须交给 SDK 运行时。
  4. 对比三种方案：只用通用编排、只嵌入编程 Agent、总控加编程子 Agent。
  5. 评估代价：集成复杂度、模型绑定、事件协议、成本与运维稳定性。
  6. 给出试点方法：选择一个可回滚任务，用端到端完成率而非 Demo 效果验收。

### 3. AI 框架选型最容易犯的错：把功能清单当成架构判断

- **分类**：个人判断
- **关联笔记**：Codex SDK 与 Agents SDK 区别及选型调研
- **核心判断**：框架选型真正重要的不是“它支持多少功能”，而是它替你承担了哪些确定性责任，以及剩下的不确定性是否仍在团队可控范围内。
- **与 AI 的真实关系**：AI 系统包含概率性决策，SDK 会预设状态、工具、审批和恢复边界；选错抽象层会让团队重复造运行时，或失去对关键业务流程的控制。
- **内容框架**：
  1. 从常见选型表切入：功能都打勾，却依然无法决定用哪个。
  2. 说明功能相似不代表抽象层、运行责任和失败模式相同。
  3. 把选型问题改写为：谁管理状态、工具、权限、恢复和验收。
  4. 结合认知锚点：软件提供确定性结构，AI 提供灵活但不确定的能力。
  5. 讨论过度封装与过度自建的两种代价，以及需要验证的官方事实。
  6. 落回行动：先画责任边界和故障路径，再阅读 API 和比较功能。
