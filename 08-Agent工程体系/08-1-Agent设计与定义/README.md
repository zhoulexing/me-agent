# Agent 设计与定义

## 核心问题

> 在 Agent 开始运行之前，如何确定它服务谁、解决什么问题、拥有哪些能力、承担多大风险，并形成可版本化的静态契约？

本领域不讲“Agent 是什么”这类基础概念，重点研究需要作出架构判断的问题。

## 深度课题

1. [**如何判断应该构建通用 Agent 还是垂直 Agent**](01-如何判断应该构建通用Agent还是垂直Agent.md)：从参照任务空间、可靠交付、开放任务处理和行动边界进行判断。
2. **如何定义 Agent 能力边界，而不是无限增加工具**：研究能力爆炸、拒绝与转交、覆盖率和可靠性的权衡。
3. **Skill、Tool、Subagent、Workflow 应该如何选择**：根据确定性、副作用、上下文隔离、状态、并行、审计和恢复要求作出选择。
4. **工具粒度应该如何设计**：比较原子工具、业务工具和万能执行工具对模型自由度、可控性与验证成本的影响。
5. **哪些信息应该放在 System Prompt、Skill、Memory 或外部状态中**：研究时效、权威性、更新频率、Token 和污染范围。
6. **如何确定 Agent 的自主程度**：比较建议、准备和执行三类授权，以及可逆性、影响范围和人工成本。
7. **如何把安全要求定义成可执行策略**：将 Prompt 原则转化为 Permission、Sandbox、Credential 和 Egress Policy。
8. **AgentSpec 应该包含什么，如何版本化**：统一 Model、Prompt、Tools、Skills、Policy、协议和成功契约。
9. **如何根据任务风险设计 Agent 架构**：判断是否需要 Workflow、独立 Verifier、专用 Sandbox 或人工闭环。

## 面试级判断标准

优秀回答不能只列组件，而要说明场景假设、候选方案、选择维度、失败边界、系统不变量以及如何验证选择有效。

## 建设顺序

优先研究能力边界和 Skill/Tool/Subagent/Workflow 选择，再进入自主程度、安全策略和 AgentSpec。每个课题都应使用同一个真实任务展示不同设计选择的后果。
