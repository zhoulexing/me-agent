# Agent 执行与任务闭环

## 核心问题

> 一个定义好的 Agent，如何在有限上下文、动态环境和真实副作用中保持目标、正确行动、验证结果并在故障后继续？

## 深度课题

1. **如何把用户请求转换成可执行、可验证的 GoalSpec**：区分用户动作、真实目标、约束、验收标准和必须澄清的歧义。
2. **如何判定任务执行过程中是否偏离目标**：综合行动相关性、约束违反、验收进展、范围扩张和连续无进展，而不是只算文本相似度。
3. **如何在有限 Context 预算下选择最有价值的信息**：权衡相关性、权威性、时效性、风险和可追溯性。
4. **如何防止错误信息和恶意信息污染 Context**：处理过期 Memory、不可信网页、错误 Tool Result、来源冲突和 Prompt Injection。
5. **上下文压缩必须保留哪些不变量**：保证目标、约束、验收标准、副作用、未完成事项和 `UNKNOWN` 不被扭曲。
6. **什么时候使用计划，什么时候使用反应式 Agent Loop**：比较环境变化、探索需求、计划维护成本和可审计性。
7. **运行时如何选择 Skill、Tool、Subagent 和 Workflow**：从当前任务需要出发，在已有能力集合中进行动态路由。
8. **如何设计 Tool Call 从请求到执行的完整控制链**：串联参数校验、权限、审批、凭证、Sandbox、副作用记录和验证。
9. **同一 Session 为什么需要顺序，不同任务如何安全并发**：研究 Queue、Busy Buffer、消息注入、Tool 并行和竞态。
10. **主 Agent 应该如何决定是否委派给 Subagent**：权衡隔离、专业化、并行收益、成本、权限和结果整合。
11. **如何区分 Tool 成功、步骤成功和目标成功**：建立 Claim、Result、Evidence、Outcome 和 Closure Policy。
12. **Agent 在什么条件下应该停止**：处理完成、部分完成、无进展、预算耗尽、权限不足和状态不明。
13. **外部副作用状态不明时为什么不能盲目重试**：研究 Crash Window、Write-Ahead、幂等、对账、补偿和人工介入。
14. **Session 恢复时应该恢复什么**：组合 Event Log、Checkpoint、Context Snapshot、Pending Tool Call 和外部状态。

## 面试级判断标准

优秀回答要能画出任务闭环，指出每个判断的事实来源和执行边界，并解释异常、并发和不可确认状态下系统如何收敛。

## 建设顺序

先深化已有两个课题，再依次完成目标偏离、能力选择、验证闭环和副作用恢复。每个课题必须包含运行时案例或时序伪代码。
