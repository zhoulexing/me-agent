# Agent 工程体系

## 建设目标

这套知识体系研究如何把概率性的模型能力，建设成可执行、可控制、可恢复、可观测、可评测并可持续迭代的 Agent 工程系统。

它既不是工具清单，也不是特定框架的使用手册。它以工程问题为主线，以 Claude Code、Codex、DeepSeek Harness 为主要研究对象，以案例、伪代码、源码证据和可验证实验沉淀长期知识。

未来可以从同一份知识源派生出：

- Agent 工程专题研究；
- 一本系统化书稿；
- 一套循序渐进的课程；
- 面向真实项目的设计与评审方法；
- 可执行的案例库和评测集。

## 写作契约

1. 二级目录固定使用 `08-1` 到 `08-4` 的四层序号，序号后连接领域名称。
2. 不批量创建只有标题的空课题。
3. 每个课题至少包含案例或说明性伪代码；工程机制类课题尽量同时包含两者。
4. 主参考项目是 Claude Code、Codex、DeepSeek Harness。
5. 其他项目只在有独立且经过核验的实践价值时作为补充。
6. 现有实现、设计建议和个人推断必须明确区分。
7. 源码事实需要附文件、调用链或官方文档证据。
8. 原始研究材料不直接等于结论；结论应经过交叉验证或实验。
9. 跨领域课题只设一个主文档，其他领域通过索引引用。
10. 正文使用稳定文件名，版本变化交给 Git 和文档元数据记录。

## 课题状态

| 状态 | 含义 |
| --- | --- |
| `seed` | 只有问题和基本结构 |
| `draft` | 已有可讨论的初稿、案例或伪代码 |
| `verified` | 关键事实已经过源码、文档或实验验证 |
| `teachable` | 已具备讲解、练习和验收设计 |
| `published` | 已对外发布或进入正式书稿、课程 |

## 推荐建设顺序

1. 先完成四层框架的边界和深度课题地图。
2. 把已有讨论沉淀成少量完整课题，而不是制造大量空文档。
3. 对 Claude Code、Codex、DeepSeek Harness 进行按课题的源码研究。
4. 补充真实案例、失败反例、决策权衡和说明性伪代码。
5. 为重要机制设计测试或评测方法。
6. 当课题达到 `verified` 后，再组织为书稿章节。
7. 当课题具备练习和验收标准后，再组织为课程单元。
