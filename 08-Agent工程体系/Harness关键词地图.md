# Harness 关键词地图

这张表是后续收集、归类和补充 Harness 知识的主入口。十二个一级关键词用于学习和检索，不表示行业统一标准，也不要求代码拆成十二个模块。范围包含 Harness 核心及其运行、治理和改进机制。

与既有体系的关系：这里按关键词检索；[Harness 架构总览](Harness架构总览.md) 按四层解释整体责任与协作。专题正文仍按四层目录保存，通过链接关联，不复制维护。

## 关键词总表

| 一级关键词 | 包含哪些词 | 它回答什么问题 |
| --- | --- | --- |
| **1. 模型** | 模型选择、Provider、协议适配、多模态、能力限制 | 用哪个模型，怎样正确调用它？ |
| **2. 指令** | 系统提示词、项目规则、角色定义、指令优先级 | Agent 应该按照什么要求做事？ |
| **3. 消息** | 用户消息、模型回复、工具调用与结果、事件、会话历史 | 人、模型和执行系统怎样交换信息？ |
| **4. 上下文** | 请求组装、信息筛选、按需加载、结果裁剪、上下文压缩 | 模型这一轮实际看到什么？ |
| **5. 工具与扩展** | 文件读写、Shell、Web、MCP、Skills、连接器、插件 | Agent 有哪些能力，怎样接入和使用？ |
| **6. 执行循环** | Agent Loop、ReAct、计划执行、重规划、停止条件 | 怎样根据反馈不断采取下一步行动？ |
| **7. 任务与编排** | 目标、计划、Subagent、Workflow、并行与依赖 | 一件复杂工作怎样拆分、组织和协作？ |
| **8. 调度** | 后台任务、异步任务、定时任务、事件触发、完成唤醒、通知 | 任务什么时候运行，等待后怎样继续？ |
| **9. 状态与恢复** | Session、任务进度、持久化、检查点、中断、取消、重试、幂等 | 做到哪里了，出错后怎样接着做？ |
| **10. 记忆** | 记忆写入、检索、排序、更新、遗忘、来源与时效 | 历史上哪些信息值得保存和再次使用？ |
| **11. 安全与权限** | 身份、授权、人工审批、沙箱、凭证、提示注入防护 | 什么能做，谁允许做，在哪里执行？ |
| **12. 验证与改进** | 结果验收、全链路监控、复盘、评测、回归 | 是否真的做成了，出问题怎样定位并改进？ |

共同观察维度：**成本、延迟与资源预算**。它们贯穿模型、上下文、工具、子 Agent、调度和重试，不必为每一类重复维护。

## 概念边界

- 消息是交互记录；上下文是为当前模型请求从消息、指令、记忆、文件等来源组织出来的信息。
- 工具提供动作；MCP 提供接入协议；Skills 提供可复用的方法、知识和资源。三者可组合，不是同义词。
- 指令表达行为要求；权限和沙箱落实实际约束。
- 目标表达最终状态，计划表达实现路径，验收检查实际证据。
- 记忆保存值得复用的历史信息；状态准确记录当前任务做到哪里、已经发生什么。
- Subagent 管委派与独立上下文，Workflow 管步骤与依赖，后台任务管等待方式，定时任务管启动时机。
- 验证判断本次结果，监控观察运行情况，复盘解释原因，评测与回归验证改动并防止再犯。
