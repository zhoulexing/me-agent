# 核心术语表

本文件统一 Agent 工程体系中的核心概念。不同项目存在不同命名时，以概念边界为准，不强行统一项目内部术语。

| 术语 | 定义 |
| --- | --- |
| Agent | 能够基于目标和环境反馈持续作出决策并采取行动的软件实体。 |
| Harness | 围绕模型建立的上下文、执行、控制、状态、验证和观测系统。 |
| Model | 负责生成文本、结构化输出或行动建议的概率模型。 |
| Provider | 提供模型 API、协议、鉴权、限流和计费的服务方或适配层。 |
| Goal | 用户希望真实世界最终达到的状态。 |
| Task | 为实现 Goal 而管理的一项工作。 |
| Plan | 对完成 Goal 所需步骤、依赖和顺序的表达。 |
| Session | 跨多轮执行持续存在的上下文、状态和身份边界。 |
| Run / Query | 宿主向 Agent 提交的一次完整调用。 |
| Turn | 一次被接纳的工作从开始到形成终态的执行边界。 |
| Step | 一次模型请求及其直接引发的工具调用和结果。 |
| Agent Loop | 组装上下文、请求模型、执行工具、接收反馈并决定是否继续的循环。 |
| Tool | 模型可以请求调用的结构化执行能力。 |
| Capability | 系统拥有的能力，可能由 Tool、Skill、子 Agent、工作流或内部服务实现。 |
| Skill | 按需加载的领域指令、知识、资源和脚本集合。 |
| Context | 模型在当前请求中实际可见的信息。 |
| Context Projection | 从 Session、事件和外部状态生成的模型可见视图。 |
| Context Snapshot | 某一轮模型实际看到的冻结上下文。 |
| Memory | 跨轮或跨 Session 保存并按需召回的信息。 |
| State | 系统当前事实，包括模型可见状态、Harness 私有状态和外部环境状态。 |
| Event | 对已经发生事实的记录。 |
| Event Log | 按顺序保存事件、支持审计和状态重建的持久记录。 |
| Checkpoint | 某一时刻整理后的可恢复状态快照。 |
| Side Effect | 对外部真实环境产生的改变。 |
| Idempotency | 同一意图重复执行时，业务效果不会重复发生的性质或机制。 |
| Reconciliation | 通过权威来源重新确认外部真实状态的过程。 |
| Compensation | 对已经发生的副作用执行预定义修正动作。 |
| Permission | 对一次具体行动是否允许的确定性判断。 |
| Approval | 对具体高风险行动的人工授权记录。 |
| Sandbox | 从执行环境层限制文件、网络、进程和资源能力的隔离边界。 |
| Credential Broker | 在不向模型暴露原始凭证的前提下代为使用凭证的组件。 |
| Verifier | 收集或判断任务结果证据的确定性工具、模型或人工角色。 |
| Evidence | 支持某项完成判断的可追溯事实。 |
| Outcome | 任务执行后真实环境所处的结果状态。 |
| Trace | 串联用户输入、模型请求、工具调用、验证和交付事件的执行轨迹。 |
| Fixture | 评测开始前准备的确定性环境和数据。 |
| Trial | 某个评测任务的一次独立运行。 |
| Grader | 根据结果、证据或轨迹进行判分的组件。 |
